# Firebase 料金体系と無料枠

## 概要
Firebaseは「Sparkプラン（無料）」と「Blazeプラン（従量課金）」の2つの料金プランがある。
個人開発や小規模アプリなら、無料枠内で十分運用可能。

---

## 現在のプラン

**Sparkプラン（無料）** を使用中

確認方法:
1. [Firebaseコンソール](https://console.firebase.google.com/project/kusoapp01/overview) にアクセス
2. 左下の歯車アイコン → 「使用量と請求額」

---

## Firebase Hosting 無料枠

| リソース | 無料枠 | 説明 |
|----------|--------|------|
| ストレージ | 10 GB | デプロイしたファイルの合計サイズ |
| 転送量 | 360 MB/日 | ユーザーがダウンロードするデータ量 |
| カスタムドメイン | 無制限 | 独自ドメインの設定 |
| SSL証明書 | 無料・自動 | HTTPS対応 |
| デプロイ回数 | 無制限 | 何度でもデプロイ可能 |

### 「今日えらっ」アプリの使用量目安

- **ビルドサイズ:** 約535KB（10GBの0.005%）
- **1アクセスあたり転送量:** 約170KB（gzip後）
- **1日の無料アクセス数:** 約2,100回（360MB ÷ 170KB）

→ **1日2,000アクセスまで無料**

## Cloud Firestore 無料枠

| リソース | 無料枠/日 | 説明 |
|----------|----------|------|
| 読み取り | 50,000回 | データの取得 |
| 書き込み | 20,000回 | データの追加・更新 |
| 削除 | 20,000回 | データの削除 |
| ストレージ | 1 GB | 保存データの合計 |
| ネットワーク送信 | 10 GB/月 | データ転送量 |

### 「今日えらっ」アプリの使用量目安

「頑張った！」ボタン1回で:
- 書き込み: 1回（clicksコレクションに追加）
- 読み取り: 1回（初回カウント取得時のみ）

→ **1日20,000回ボタンを押しても無料**

## 無料枠を超えた場合

### Sparkプラン（無料）の場合
- 無料枠を超えるとサービスが**一時停止**
- 課金は発生しない（安心）

### Blazeプラン（従量課金）の場合
- 無料枠を超えた分だけ課金
- 予算アラートを設定可能

## なぜGoogleは無料で提供するのか

### 1. 開発者エコシステムの拡大
- 無料で使い始めてもらい、Firebase/GCPに慣れてもらう
- 将来的に大規模プロジェクトで有料プランを使ってもらう

### 2. 従量課金モデル
- 使った分だけ払う仕組み
- 小規模なら$0、大規模になったら収益化

### 3. 競合との差別化
- AWS Amplify、Vercel、Netlifyとの競争
- 無料枠の充実で開発者を獲得

### 4. データ収集（間接的）
- 利用状況の分析でサービス改善
- ただし、ユーザーデータの販売はしない（Google Cloud規約）

## 無料で運用するためのTips

### 1. 不要なデータを定期削除
```javascript
// 古いclicksデータを削除する例
const thirtyDaysAgo = new Date();
thirtyDaysAgo.setDate(thirtyDaysAgo.getDate() - 30);

const oldClicks = await getDocs(
  query(collection(db, 'clicks'), where('timestamp', '<', thirtyDaysAgo))
);
oldClicks.forEach(doc => deleteDoc(doc.ref));
```

### 2. 読み取りを最小化
- リアルタイムリスナー（onSnapshot）の使いすぎに注意
- 必要なデータだけ取得（クエリを絞る）

### 3. キャッシュを活用
- Firestoreのオフラインキャッシュを有効化
- ブラウザキャッシュでHosting転送量を削減

### 4. 画像は外部サービスを使用
- 大きな画像はCloudinaryやImgixを使用
- Firebase Storageは転送量が高め

## 課金が心配な場合の対策

### 1. Sparkプランのまま運用
- 無料枠を超えるとサービス停止（課金されない）
- 小規模アプリなら十分

### 2. Blazeプランで予算アラート設定
```
Firebaseコンソール → 歯車 → 使用量と請求額 → 予算アラートを設定
```
- 例: $5を超えたらメール通知

### 3. 使用量上限を設定
- Cloud Functionsの同時実行数を制限
- Firestoreのセキュリティルールでレート制限
